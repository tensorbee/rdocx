# CLAUDE.md

Guidance for coding agents working in this repository.

`.claude/WORKFLOW.md` wins on any process question. This file describes the
repository. That one describes how work lands in it.

## What this repo is

A Rust workspace for Office Open XML. Three families of crates:

- **`oxml-*`**, format-neutral OOXML infrastructure. The OPC container, units,
  DrawingML, image handling, layout primitives, the PDF backend.
- **`rdocx-*`**, WordprocessingML. A shipped port of `python-docx`, prepared at
  0.13.0 across the exact seven-package stable family. The immutable v0.11.0
  attempt published only `rdocx-opc` and `rdocx-oxml`, and 0.12.0 remains the
  latest complete stable family until the separately approved release.
- **`rpptx-*`**, PresentationML. A port of `python-pptx`, under construction.

The repository is named `rdocx` for historical reasons and keeps that name
deliberately: renaming it would buy a more accurate name and cost a redirect
that breaks the moment anything is created at the old path.

Read `docs/hld/00-vision.md` first, then `03-architecture.md`.

## Read first

- **Every compile and test task runs natively.** There is no dev container.
- **The hash harness gates every PR in M1 through M6.** An unexplained output
  delta blocks the merge. Never fold a behaviour change into a file move.
- **Rendering baselines require deterministic font mode.** System fonts differ
  between machines, so a baseline recorded against them is worthless.
- **No em-dash, no prose semicolon** in tracked Markdown or commit messages.
- **Never `Co-Authored-By`.**

## Layout

| Path | What |
|---|---|
| `crates/oxml-*` | Format-neutral infrastructure. **Must not depend on `rdocx-*` or `rpptx-*`.** No exceptions: the `Theme` adapter lives in `rdocx-oxml`, so that edge runs `rdocx-oxml -> oxml-drawing` |
| `crates/rdocx-*` | WordprocessingML. `rdocx-oxml` holds the `w:` types, `rdocx-layout` the flow engine and paginator, `rdocx` the facade |
| `crates/rpptx-*` | PresentationML. `rpptx-oxml` the `p:` types, `rpptx-layout` the inheritance resolver, `rpptx-render` the slide renderer, `rpptx` the facade |
| `crates/oxml-layout/fonts/` | 24 bundled TTFs compiled unconditionally. The optional `system-fonts` feature adds host discovery. Every family needs a licence file |
| `crates/rpptx/assets/` | The bundled `default.pptx`. **Must live under the crate directory** or it is not in the published tarball |
| `docs/hld/` | The spec set, 00 to 15. Precedence rule in `docs/hld/README.md` |
| `docs/sprints/` | BACKLOG, SPRINT_PLAN, CURRENT_SPRINT, SPRINT_TRACKER, AS_BUILT |
| `.claude/` | WORKFLOW.md, `commands/`, `skills/`, design plans, reviews, worker handoffs |
| `.agents/skills/` | **Generated** Codex adapters for the same commands and skills. Never hand-edited. `scripts/sync_agent_skills.py` owns them |
| `samples/` | Generated output, gitignored. Regenerated by an example, not a fixture source |
| `scripts/` | Gate scripts and the sprint state machine |
| `tools/gen-presets/` | Offline generator for the preset shape table. Output is checked in |

## Build and test

```bash
cargo check -p <crate> --all-targets        # the inner loop
cargo test -p <crate>                       # per-crate, preferred per F-ID
cargo test -p <crate> --test <file>         # one integration binary, fastest
cargo test --workspace --all-features --exclude rdocx-py --exclude rpptx-py
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo fmt --all --check
cargo test -p oxml-layout --no-default-features   # the system-font-discovery-off path
cargo check --target wasm32-unknown-unknown -p rdocx-wasm -p rpptx-wasm

python3 scripts/hash_harness.py --check     # gates every PR in M1-M6
python3 scripts/prose_check.py              # the voice rules
python3 scripts/sync_agent_skills.py --check  # Codex adapters match their source
```

- **`--exclude rdocx-py --exclude rpptx-py` is required, not cosmetic.**
  `pyo3/extension-module` tells the linker that Python symbols come from the
  host interpreter, which is false for a test binary. On Linux it is an
  unresolved-symbol link failure that is easy to misdiagnose.
- Iterate scoped. Never `cargo clean`.
- Adding a file under a `tests/` directory creates another binary to link. Add a
  module to the existing integration entrypoint instead.

The gate is `/verify`. The list above is the inner loop, not a second source of
truth for what must pass.

## Workflow essentials

- The atomic rhythm is `/design`, `/start-feature`, implement, `/microscope`,
  `/verify`, `/complete-feature`. `/microscope` is not skippable.
- Parallel work adds `/claim-feature`, `/complete-feature --prepare` and
  `/integrate-feature`. `/run-sprint` drives all of it for a whole sprint.
- Sprint branches are `sprint/sNN` off `main`. Worker branches are
  `work/<fid-lower>-<agent>`.
- Worker branches and worktrees remain available through sprint verification
  and review. `/close-sprint` removes clean completed workers after pushing
  `main` and the sprint tag.
- **Editing a command or skill means regenerating `.agents/skills/`.** `/verify`
  fails on drift.
- **Only `/close-sprint` may merge to `main` or create an `sNN` sprint tag.**
- **Only `/release` may create or push a `v*` release tag or start crates.io
  publication.** It requires a separate final approval at the reviewed SHA.
- The design plan is a machine-consumed contract. Its `## HLD impact` section is
  a file list that `/complete-feature` executes against, which is what keeps the
  spec set from rotting.
- Commit subject is `F-XXX, short title`, with `Tests,` and `Harness,` trailer
  lines.
- Do not commit or push unless the invoked workflow explicitly says to.

## Structural rules

The codebase must stay easy to reason about locally. A reader should be able to
answer "what does this do?" from one file.

**The test for any new construct**: does it *reduce the number of cases a reader
must consider*, or *increase the number of places they must look*?

Reducing cases is good even when it adds types. A newtype that makes `Twips` and
`Emu` non-interchangeable, or a type that makes an invalid state
unrepresentable, is worth it.

Increasing places to look is not:

- No new trait unless two implementers exist **today**.
- No new generic parameter unless instantiated two ways **today**.
- No `Box<dyn>` where the concrete type is statically known.
- No wrapper that only forwards.
- No new feature flag without a named consumer.
- No new crate, module or file without asking first.
- Smallest diff that solves the problem. No speculative extensibility.
- Match the conventions of the file you are editing.

Note the converse failure, which is equally real: a sprawling function that
trips a complexity lint needs *more* structure, not less.

## Domain conventions

- **quick-xml pull parsing only.** No serde, no derive, no macros, no codegen.
  Every parser and serialiser is hand-written. This is deliberate.
- Types follow spec names, `CT_*` and `ST_*`, under
  `#![allow(non_camel_case_types)]`.
- Root parts get `from_xml(&[u8])` and `to_xml(&self)`. Nested elements take a
  `&mut Reader` and a `&mut Writer`.
- **Prefix-tolerant on read, fixed prefix on write.**
- **Unmodelled subtrees are preserved verbatim** through
  `oxml_core::raw_xml::capture_element`. Parse only what you render, preserve
  the rest. This is the scope control for PresentationML.
- **OOXML schemas are `xsd:sequence`.** Child order is part of the contract, and
  getting it wrong makes PowerPoint refuse the file rather than warn.
- `thiserror`, never `anyhow`.
- Edition 2024, MSRV 1.93, toolchain pinned in `rust-toolchain.toml`.

## Things that are deliberately wrong

Do not "fix" these without reading why:

- **`rdocx_oxml::theme::apply_tint_shade`** uses Word's 0-255 convention and a
  naive sRGB interpolation. It feeds every rendered PDF. Correcting it during
  the migration would change every theme colour in a way indistinguishable from
  a migration bug. `oxml-drawing` adds spec-correct functions under different
  names. See `docs/hld/05-drawingml-model.md`.
- **Unit constructors truncate** with `as i64`. Pinned by tests. Changing it to
  rounding shifts every twip, which shifts layout.
- **`rdocx-oxml`'s `drawing.rs`** keeps its `wp:` code. It is Word-only and is
  not migrated.
