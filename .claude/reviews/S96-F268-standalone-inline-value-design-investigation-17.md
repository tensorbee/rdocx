## Complete selected model graph

CT_P and CT_R derive Clone and PartialEq. Their public fields contain several paths outside a safe inline-only graph: paragraph controls, revisions, equations, ruby and hyperlinks, raw/bookmark/comment metadata, run alt_drawings and the RunContent::Field variant. Continue rejecting those paths. Paragraph properties can contain tab-stop and other policies and should remain None in the initial inline branch. Run properties should also remain None in that branch unless a separately reviewed exact finite RPr policy is actually needed. Preserve all existing plain-text behavior through the original helper rather than duplicating or broadening its property projection. References: `crates/rdocx-oxml/src/text.rs:9059`, `crates/rdocx-oxml/src/text.rs:9642`, `crates/rdocx-oxml/src/text.rs:17196`.

The closed positive inline graph is CT_P to CT_R to RunContent::Drawing to CT_Drawing with inline Some and anchor None. CT_Inline consists only of integer/Boolean values, Emu dimensions, owned Strings, optional SourceRect and optional owned raw XML bytes. SourceRect contains four i32 values. It derives ordinary Clone/PartialEq. There is no Cell, RefCell, OnceLock, Mutex, Arc-owned private reader, SourceMap, Field or recursive paragraph within CT_Inline. Full equality and clone on this selected graph therefore perform stored-value work rather than fresh identity creation or hidden XML reads. References: `crates/rdocx-oxml/src/drawing.rs:130`, `crates/rdocx-oxml/src/drawing.rs:1403`, `crates/rdocx-oxml/src/drawing.rs:2145`.

Allowing Drawing without explicitly excluding anchor would reopen private Field and recursive-owner reasoning. Both inline-and-anchor and neither-inline-nor-anchor values must miss the initial inline branch. Alternate-content/layout drawings remain excluded through alt_drawings and run raw metadata. Its drawing path still invokes the existing drawing reader and captures/decodes exact raw input on a miss. The certificate would prove a previously returned owned value only. ## Concrete equality obstacles

CT_Inline::new sets raw_xml=None. Document's actual picture producer constructs that value, places it in a drawing-only run and appends its paragraph. The actual CT_Drawing reader instead captures the inline XML, closes the required scope and sets raw_xml=Some(stored). Derived complete equality includes this field. Thus a freshly authored staged picture root cannot qualify against that actual reader output merely because its visible picture attributes agree. References: `crates/rdocx-oxml/src/drawing.rs:1432`, `crates/rdocx-oxml/src/drawing.rs:1445`, `crates/rdocx-oxml/src/drawing.rs:2427`, `crates/rdocx-oxml/src/drawing.rs:2466`, `crates/rdocx/src/document.rs:40499`.

Opened reader-produced inline values may have raw_xml on both sides, but exact equality is still factual. The stored raw closure depends on the introduced/lost namespace bindings. The run reader also scans actual drawing raw bytes for external namespace use, preserves root attributes and appends retained/local binding records to extra_xml with encoded positions. Complete CT_P equality compares those records too. A minimal extension retaining empty run extras can therefore reject common parsed drawing paragraphs. That is a legitimate conservative miss, not permission to erase records or compare a projected picture. References: `crates/rdocx-oxml/src/drawing.rs:2409`, `crates/rdocx-oxml/src/drawing.rs:2454`, `crates/rdocx-oxml/src/text.rs:10459`, `crates/rdocx-oxml/src/text.rs:10479`, `crates/rdocx-oxml/src/text.rs:10542`, `crates/rdocx-oxml/src/text.rs:30526`.

Raw inline bytes are ordinary owned value data, not a hidden private identity. Nevertheless, the narrow contract does not silently admit all run raw children or generated namespace-record forms. If actual useful candidates require those forms, Root must first enumerate their exact representation and close that additional language explicitly. A blanket raw allowance, stripping namespace records, ignoring raw_xml, reparsing staged bytes to replace the first reader, or retaining a new parsed AST is outside this proposal.

## Minimal finite option and adoption discriminators

The smallest safe option keeps the existing plain branch unchanged and admits a separate branch containing at least one inline picture. That branch requires paragraph properties None and all paragraph metadata/projection vectors empty, every run's properties None, extra_xml/extra_xml_positions/alt_drawings empty, and each run item either the existing finite ASCII alphanumeric/space CT_Text value or a Drawing with inline Some and anchor None. For the first bounded picture domain, require nonempty embed_id with no link_id or chart_rel_id. All inline scalar, description/title/name, decorative/crop and exact raw bytes remain included in full equality. Unknown, chart, linked, floating, private and raw-run forms keep the literal reader. This is a technically feasible option, not a selection.

Keep the existing full-input holds_field_words check before both value checks and full equality. It scans the complete source XML for fldChar/fldSimple spellings and can conservatively reject opaque inline bytes as well. It must not be weakened because a particular Drawing has no typed Field. Explicitly reject Field, bookmarks, tabs, reference/range markers, controls, revisions, ruby, equations and nonfinite text/property paths in the new branch.
