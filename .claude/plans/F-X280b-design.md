## Approach

### 1. Shared OPC read contract

Keep this in `crates/oxml-opc/src/package.rs`. The OPC layer must not depend on `rdocx` or `rpptx`.

- Duplicate exact names. Always call `pre_index_entry_count` on both bounded and unbounded reads. If it cannot read the end record, return the ZIP error. After `ZipArchive::new`, if the central-directory count is greater than `archive.len()`, scan the central directory before any part is inserted and return `OpcError::DuplicatePartName(first_repeated_normalized_name)`. Normalize as part names are normalized and compare case-insensitively. This runs on the `PackageReadLimits::UNBOUNDED` path used by `OpcPackage::open` and `OpcPackage::from_reader`, not only the bounded path. If the scan cannot produce a repeated part name, return an invalid-ZIP error, not a nameless duplicate success. The refusal must name `word/document.xml` or `ppt/slides/slide1.xml` for the Issue 435 cases. This replaces the donor fallback string `an entry stored twice`, which does not name the part.
- Forbidden XML characters. After `[Content_Types].xml` is parsed, for every entry recognized as XML by `is_xml_entry`, call the existing `first_invalid_xml_character`. If one is found, return `OpcError::InvalidXmlCharacter { part, code_point, line, column }` before returning the package. This is atomic and covers both `word/document.xml` and `ppt/slides/slide1.xml`. It does not sanitize and does not rewrite to `_x0001_`. Binary and non-XML parts are not scanned. Well-formed opaque XML is unchanged.
- Keep `write_to`'s existing `reject_written_xml_characters` for newly written XML characters. The `malformed_source_entries` carve-out no longer applies to XML entries because open refuses them. It remains irrelevant to binary and non-XML entries. No save writes a newly introduced forbidden character.
- Validators catch `OpcError::InvalidXmlCharacter` from read and turn it into an error finding or issue naming the part, so `validate` reports rather than raising for this content fault. Other package decode errors, including duplicate names, propagate as `OpcError` or `rpptx::Error`. The CLIs exit 1 and print the part name.

- Build footnote and endnote id sets from the related notes parts with the same `package.get_part_rels` and `resolve_rel_target` calls open uses.
- For each story part, run `document_story_findings` with a bounded subset:
  - child order and allowed children of `w:body`, `w:p`, and `w:r` from the transitional schema lists.
  - `w:pPr` first in `w:p` and `w:rPr` first in `w:r`.

  - `w:jc` values for `ST_Jc` and `ST_JcTable`, and `w:color` as `auto` or six hexadecimal digits.
  - required `w:id` and `w:author` on `w:ins`, `w:del`, `w:moveFrom`, and `w:moveTo`.
  - `wp:extent/@cx`, `wp:extent/@cy`, `a:ext/@cx`, and `a:ext/@cy` in `0..=27_273_042_316_900`.

- Update `rdocx validate` help in `crates/rdocx-cli/src/main.rs` and `crates/rdocx-cli/README.md` to name the subset explicitly: package, well-formed XML 1.0, style ids, body/p/r child order and allowed children, text placement, jc and color, tracked-change id and author, extents, m:rad required children, relationship ids, note references, and deleted text. ### 4. `rpptx` stored-package validation

Add `pub fn validate_presentation_file(path: impl AsRef<Path>) -> Result<Vec<ValidationIssue>>` in `crates/rpptx/src/lib.rs`.

- Read bytes with `std::fs::read` and open with `OpcPackage::from_reader`.
- If open returns `OpcError::InvalidXmlCharacter`, return a single `ValidationIssue::InvalidXmlChild { part, path: "/", message }` naming the part and code point.
- Otherwise call `stored_package_issues(&package)`:
  - every XML part whose content type lowercased ends `xml` is checked by `stored_xml_fault` for parser error, root count, unclosed depth, and strict XML 1.0 forbidden characters.
  - every internal relationship target of type slide, layout, master, notes slide, notes master, or handout master must have its expected content type. A missing or fallback `application/xml` is `MissingContentTypeOverride { part }`.
  - `presentation.xml` children must follow `CT_Presentation` order. Unknown children are `InvalidXmlChild`.
  - slide, layout, master, notes, and handout parts are checked for unknown shape-tree children, `p:cNvPr` missing `id` or `name`, and a table row cell count that differs from the `a:gridCol` count.
- Then `Presentation::from_read_package(package)`. If it opens, append `presentation.validate()` issues, deduplicated. If it fails and stored issues exist, return the stored issues. If it fails with no stored issues, return the error.
- CLI `rpptx validate` uses `validate_presentation_file`, prints each issue with `{issue}` using its existing Display implementation, and exits 1 if any. Update `crates/rpptx-cli/src/main.rs` help and `crates/rpptx-cli/README.md` to name the stored-package checks and say it is not a full schema validator.

### 6. Shape size guard

- Use it in `textbox_member`, `preset_member`, and `unstyled_preset_member`. Keep `table_member` and `add_table` unchanged. `add_connector` uses its existing `connector_transform`.

- Zero width or height remains allowed. All four arguments are required, with no defaults. Units are EMU as `i64`. Negative values are rejected by sign. Positive values pass to the existing transform with no rounding or truncation change.
