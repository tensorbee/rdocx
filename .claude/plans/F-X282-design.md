## Problem

The issue is correct output with edit cost that grows with unrelated data. The mechanisms below are the accepted preparation pins. Evidence pins records which of them were re-read in the current worktree.

- `Document::flush_to_package` serializes the entire styles model with `CT_Styles::to_xml` on every flush, then parses the whole styles part with `CT_Styles::from_xml` to decide whether it changed. See `crates/rdocx/src/document.rs:26159-26190` and `crates/rdocx-oxml/src/styles.rs:1661-1694`. A 419 KB styles part therefore adds parse and serialization work to every edit. The current worktree still has `to_xml()?` at `26165`, `from_xml(xml).ok()` at `26181`, and `set_part` at `26190`.
- `Document::clone_for_staging` clones `CT_Styles` by value. See `crates/rdocx/src/document.rs:22739-22756` and the field at `crates/rdocx/src/document.rs:7232`. A staged clone copies the full styles model even when no style is edited. The current field is still `pub(crate) styles: CT_Styles` at `7232`.
- A cell paragraph edit resolves through `Document::cell_paragraph_story_location`, which clones the document, serializes the body with `to_xml`, scans every table-cell story owner, and for each owner scans story owners again. ## Approach

No new crate, module, file, trait, feature flag, or test binary. One generic parameter is added on `edit_cell_paragraph<T>` because two return types already pass through the `Cell` arm today. Contract closure: every promised operation below names its callable and an A-ID. The cache order in `Styles open proof and publication cache` is the single definition of a hit. Full revalidation of every frozen line remains pending. The Evidence pins spot check did not invalidate this contract.

### Styles open proof and publication cache

Use the existing `OpcPackage` part map, which already stores `Arc<Vec<u8>>` values. See `crates/oxml-opc/src/package.rs:69-80`.

Add one additive accessor in `oxml-opc`:

```rust
pub fn get_part_shared(&self, part_name: &str) -> Option<&Arc<Vec<u8>>>
```

It uses the existing private `deterministic_part_key` and returns the shared bytes without mutation. See `crates/oxml-opc/src/package.rs:537` and `crates/oxml-opc/src/package.rs:894`. The existing `get_part` stays `Option<&[u8]>`. The existing `set_part` stays unchanged. See `crates/oxml-opc/src/package.rs:553`. Current worktree reads still show `get_part` at `537`, `set_part` at `553`, and `deterministic_part_key` at `894`. `get_part_shared` is absent. This is a documented additive method on oxml-opc 0.15 and is semver-minor for the shared family. `rdocx` 0.17 is the named consumer through the styles cache. A `#[doc(hidden)] pub` twin would still be public SemVer, so the documented form is the closure.

Proposed internal shape:

```rust
pub(crate) styles: Arc<CT_Styles>,
pub(crate) styles_part_cache: Option<StylesPartCache>,

struct StylesPartCache {
    bytes: Arc<Vec<u8>>,
    parsed: Arc<CT_Styles>,
    proof: StylesSerializationProof,
}

enum StylesSerializationProof {
    Serializable,
    Unserializable,
}
```

At open, after `CT_Styles::from_xml` succeeds, call `CT_Styles::to_xml` once and record `Serializable` or `Unserializable`. This call is before any timed edit. The parsed model and the bytes `Arc` are stored.

`Document::from_package_reusing` gains an internal `styles_read` argument. When the resolved styles part bytes are `Arc::ptr_eq` with the carried bytes, it reuses the carried parse and proof. Otherwise it parses the part and proves once. See `crates/rdocx/src/document.rs:24632-24700` and `crates/rdocx/src/document.rs:24698`. The current worktree still calls `CT_Styles::from_xml` at `24698`.

`Document::clone_for_staging` clones the `Arc<CT_Styles>` and the `styles_part_cache`. See `crates/rdocx/src/document.rs:22739-22756`.

`reopen_prepared_staged` is `crates/rdocx/src/document.rs:25395-25413`. It calls `reopen_staged` at `25461`. The in-memory arm calls `from_package_reusing` at `25480` and passes the carried styles cache. Reuse requires `Arc::ptr_eq` on the styles bytes. The zip arm at `25492` calls `from_bytes_with_limits`, which allocates a new bytes `Arc`, so that arm parses and proves once. Case 1 release timing uses `saves_as` at `25116-25121`, which stops at `saved_package` and does not reopen. The `to_bytes` comparison inside `saves_as` at `25133-25147` is `debug_assertions` only and is not the release Python 3.12 gate.

`Document::flush_to_package` replaces the unconditional serialize-and-parse block with `styles_differ_from_part`. See `crates/rdocx/src/document.rs:26159-26190`.

The helper decides a cache hit only in this order. Current styles part bytes `Arc` identity is the first condition.

- The current styles part bytes `Arc` must be pointer-equal to the cached bytes `Arc`. If it differs, the lookup is a miss even when the model `Arc` is pointer-equal. Model pointer equality alone never suppresses inspection after a part replacement. Discriminator: open a document, call `package.set_part("/word/styles.xml", new_valid_bytes)`, then flush without touching the model. The helper parses the new bytes and does not return a stale-bytes hit. On `Document`, `package` is `pub(crate)` at `document.rs:7207`. That visibility was re-read.
- After that bytes identity, a model `Arc` that is pointer-equal to the cached parsed `Arc` is a hit. If the proof is `Serializable`, return `false` and write nothing. If the proof is `Unserializable`, call `to_xml` again to preserve the exact error and return `Err` before `set_part`.
- After that bytes identity, a model that value-equals the cached parsed model is a hit. If the proof is `Serializable`, adopt the cached `Arc` and return `false`. If the proof is `Unserializable`, call `to_xml` again and return `Err` before `set_part`.
- After that bytes identity, a model that differs returns `true`.
- Cache miss: parse the part bytes. If `from_xml` fails, return `Err` before `set_part`. If parse succeeds, call `to_xml` once and record the proof. If the model value-equals the parsed model and the proof is `Serializable`, adopt the parsed `Arc` and return `false`. If value-equals and the proof is `Unserializable`, call `to_xml` again and return `Err`. If the model differs, return `true`.
- No part: return `true` and write the default styles.

On `true`, serialize the current model, run `retain_styles_root_attributes`, and call `set_part` only after both succeed. See `crates/rdocx/src/document.rs:2753-2820`. On any error, return before `set_part` and leave the cache unchanged. A writer error is never recorded as `Serializable`. After both succeed, read the installed bytes back with `get_part_shared` and store that `Arc`, the published model `Arc`, and `Serializable`. The next unchanged flush hits that cache and does not re-prove. The A282-1 unchanged path still uses the open proof and does not depend on this refresh.

Every style mutation path uses `Arc::make_mut` on the candidate or owned document. The original document keeps its shared `Arc` until publication succeeds. Where a deep model clone is genuinely required, use `CT_Styles::clone(&self.styles)` rather than `self.styles.clone()`, which would clone only the `Arc`.

The claim that `from_xml` success implies `to_xml` success is withdrawn. The design does not rely on it. The open-time proof is the evidence. If the proof fails, the equal-model skip is refused and the flush preserves the existing failure. The proof is not placed on the first timed flush. The writer reparses retained raw fragments with an empty inherited scope at `crates/rdocx-oxml/src/styles.rs:842-899`, `:191-242`, `:548-689`, `:953-994`, `:1257-1309` and `:2159`. `CT_BorderEdge::to_xml` also reads a retained source root as `Event::Start` and returns `Err("started border source root missing")` when it is not a started element. See `crates/rdocx-oxml/src/borders.rs:168-203`. A model can therefore fail `to_xml` even when a part parsed. The open-time proof catches that class and refuses the skip.

### Cell and run route

`ParagraphLocation::edit` for `Cell` calls `Document::edit_cell_paragraph`. The method is `#[doc(hidden)] pub` on `rdocx::Document`. Hidden rustdoc does not remove it from the public surface. It is an additive item on the rdocx 0.17 strict SemVer baseline. Existing `Document` signatures stay. `Paragraph.inner` is `pub(crate)` at `crates/rdocx/src/paragraph.rs:887`, so `rdocx-py` cannot assign the live `CT_P`. The named consumer is the `Cell` arm of `ParagraphLocation::edit`.

The method has one generic parameter. A `Result<()>`-only signature is too small. Two return types already pass through that `Cell` arm into `edit_story_paragraph<T>` at `crates/rdocx/src/document.rs:32864`:

1. `()` from `apply_run_update` at `crates/rdocx-py/src/formatting.rs:461-464`, from `apply_paragraph_update` at `crates/rdocx-py/src/formatting.rs:1280`, and from `Paragraph::set_alignment` at `crates/rdocx-py/src/paragraph.rs:1054-1056`.
2. The run index paired with its accepted run path from paragraph append at `crates/rdocx-py/src/paragraph.rs:624-640`.

```rust
#[doc(hidden)]
pub fn edit_cell_paragraph<T>(
    &mut self,
    table: usize,
    row: usize,
    cell: usize,
    paragraph: usize,
    edit: impl FnOnce(&mut Paragraph<'_>) -> Result<T>,
) -> Result<T>
```

This is the same generic shape as the existing story editor. It is not a trait, not a feature flag, and not a second public abstraction. The generic is present because those two return types exist today.

The bridge behaves as follows. Every fallible step runs before any live invalidation.

1. Resolve the table immutably with a private `nth_table_in_body_ref` helper that mirrors `nth_table_in_body` (`crates/rdocx/src/document.rs:20627`) and does not call `invalidate_layout`. Resolve the cell with `TableRef::cell` (`crates/rdocx/src/table.rs:2627`). The helper is a private twin with one caller, added because the existing mutable lookup invalidates live state before eligibility.
2. Count reader paragraphs with `CT_Tc::paragraphs()` (`crates/rdocx-oxml/src/table.rs:2267`) and direct paragraphs by counting `CellContent::Paragraph` in `cell.inner.content`. The mutable accessor `CT_Tc::paragraphs_mut()` (`crates/rdocx-oxml/src/table.rs:2274`) filters only direct paragraphs.
3. If the counts differ, or `paragraph >= direct_count`, drop the borrow and take the existing checked route: `cell_paragraph_story_location` (`crates/rdocx/src/document.rs:35472`) then `edit_story_paragraph` (`crates/rdocx/src/document.rs:32864`). The closure is invoked at most once on that route. A valid source that reaches the edit invokes it once. A resolver refusal for an invalid owner or out-of-range ordinal invokes it zero times and changes nothing.
4. Otherwise clone the selected direct `CT_P` from the immutable reader sequence into `original` and clone that into `candidate`.
5. Run the closure once on `Paragraph { inner: &mut candidate }` (`crates/rdocx/src/paragraph.rs:887`). An `Err` drops both clones and returns before any mutable access. The layout caches, the checked-body refusal memo and the live paragraph are unchanged.
6. Build the candidate fragment with `ContentFragment::paragraph(candidate.clone())?` (`crates/rdocx/src/document.rs:1568`). This is the same serialization and single-item admission the checked editor performs at `crates/rdocx/src/document.rs:32874`.
7. Refuse section ownership with `reject_section_owning_content_fragment(&fragment)?` (`crates/rdocx/src/document.rs:14131`).
8. Probe the serialized candidate with `validate_strict_xml_1_0(&fragment.xml)` (`crates/oxml-core/src/xml.rs:55`). Success is a sufficient qualification for the direct path, not a rejection gate. The validator checks UTF-8, XML 1.0 characters, qualified names, namespace binding, attribute value syntax and expanded-attribute uniqueness at `crates/oxml-core/src/xml.rs:55-76` and `:172`. That is broader than the character-only OPC writer at `crates/oxml-opc/src/package.rs:759-775`. A lexical error records the candidate as not strictly qualified and does not return. It leaves the actual acceptance or refusal to the existing checked publication in step 10.
9. Qualify the candidate for direct assignment. It is qualified only when all four hold: the strict probe in step 8 succeeded, the candidate fragment carries no relationship id, its comment marker counts do not decrease against `original`, and the document carries no retained nested modeled namespace owner that a model-only edit could strand. Extract relationship ids with `xml_relationship_ids_in_order_with_bindings` (`crates/rdocx/src/document.rs:6347`) using the fragment namespace scope, the same extractor `validate_fragment_relationships` uses at `crates/rdocx/src/document.rs:15073`. Build the `original` fragment the same way and extract comment markers with `comment_source_markers` (`crates/rdocx/src/comments.rs:2657`) from both fragments, then compare id and family counts. A relationship id, a marker decrease, an extraction error, a strict error, or a non-empty retained-owner fact means the candidate is not locally qualified. The retained-owner fact is the existing cached `plain_local_edit_blocked` field (`crates/rdocx/src/document.rs:7217`). It is set at open by `plain_local_edit_facts` (`crates/rdocx/src/document.rs:4063-4088`) and at `set_story_source_xml` (`crates/rdocx/src/document.rs:15324-15330`), copied by `clone_for_staging` (`crates/rdocx/src/document.rs:22746`) and recomputed by `flush_to_package` (`crates/rdocx/src/document.rs:26620`). It is a cached per-source fact, not a per-setter body scan. It is the same qualification the existing direct body paragraph replacement uses at `crates/rdocx/src/document.rs:35801-35816` and the plain removable paragraph check uses at `:31616-31642`.
10. For an unqualified candidate, do not rerun the closure. Resolve `cell_paragraph_story_location`, set `source_part_name`, `source_story_kind` and `source_owner_index` from that location on the already-built fragment, and publish through `replace_story_content` (`crates/rdocx/src/document.rs:31210`). That call runs the existing relationship admission and `reconcile_comment_removal` (`crates/rdocx/src/comments.rs:3487`) against the actual candidate and keeps the checked publication atomic. It is also the actual acceptance decision for a strict-unqualified candidate: a retained fragment that the current checked publisher accepts keeps that acceptance, and a newly introduced U+0000 is refused before commit by the existing OPC character policy at `crates/oxml-opc/src/package.rs:759-775`. The fallback adds no new public refusal policy and leaves the live model, layout Arc and style unchanged on any error.
11. For a qualified candidate, reacquire the same owner mutably without invalidating first. Call `nth_table_in_body` (`crates/rdocx/src/document.rs:20627`) on `self.document.body.content`, then `Table::cell` (`crates/rdocx/src/table.rs:2007`) and `Cell::paragraph_mut(paragraph)` (`crates/rdocx/src/table.rs:2291`). Require the direct count to still equal `direct_count`, the ordinal to be in range, and `*paragraph.inner == original`. A mismatch returns an error before assignment. Assign `candidate` to that direct slot, end the mutable borrow, then call `self.invalidate_layout()` (`crates/rdocx/src/document.rs:24947`) and return `Ok(result)`. No fallible operation follows the assignment. The owner-free qualification means the later flush scans no retained owner and `replay_nested_namespace_declarations_with_spans` returns the serialized bytes unchanged at `crates/rdocx/src/document.rs:4125-4127`.

Why this closes C282-1. `Document::table_mut` (`crates/rdocx/src/document.rs:34754`) clears `layout_cache`, `deterministic_layout_cache` and `unsavable_body_edit_cache` through `invalidate_layout` (`crates/rdocx/src/document.rs:24947`) before it resolves the table. The bridge never calls `table_mut`. Every fallible closure and admission step runs on immutable borrows or owned clones. The layout Arc and refusal memo change only after the assignment succeeds. A failed closure leaves the same layout Arc and the original style, matching the checked editor's failure barrier. A valid successful edit is the control that changes the style and invalidates the layout.

Why this closes C282-2. Closure `Ok` is not publication. The direct route admits the candidate through `ContentFragment::paragraph`, section refusal, the strict lexical probe, relationship and comment checks, and the retained-owner qualification. A candidate with relationship ids, removed comment markers, a strict lexical error or a non-empty retained-owner fact goes through the actual `replace_story_content` publication, so source, namespace, resource, relationship, style and comment facts are bound to the actual candidate rather than only the pre-edit source. A qualified direct assignment keeps the paragraph model's retained raw XML and the document namespace frame, so unmodelled paragraph XML is preserved verbatim. `Normal` passes the strict probe and publishes directly. `Bad\0Style` fails the strict probe and is refused by the checked fallback through the existing OPC character policy with the same U+0000 refusal class, leaving the live model, layout Arc and style unchanged. No invalid candidate is installed before a later error. `FnOnce` is invoked at most once overall. It runs once on a source that passes resolution and paragraph admission and reaches the edit, including a closure `Err` and a later candidate fallback. A preflight invalid-owner or out-of-range refusal invokes it zero times and changes nothing. The two return types still flow through `<T>`.

Why this closes C282-3. Strict validation is sufficient qualification, not a blanket gate. The four probe fragments that the existing checked publisher accepts (`duplicate_expanded_attr.xml`, `literal_lt.xml`, `numeric_name.xml` and `unbound_name.xml`) fail the strict probe and are published through `replace_story_content` with the already-built fragment and one closure invocation. The ordinary fragment passes the probe and stays on the direct path. A newly introduced U+0000 is refused through the same checked publication, not through a new public policy. The checked publisher remains the authority for legacy retained-source acceptance and refusal. Root-authored counterfactual evidence is recorded in Evidence pins. Implementation-Base revalidation remains required.

Why this closes the whole-document replay lead. A model-only paragraph assignment leaves the package bytes stale, so the next flush serializes the body and replays the nested modeled namespace owners scanned from those bytes at `crates/rdocx/src/document.rs:26522-26606`. Root's counterfactual showed that checked cell edits and saves succeed on four generated documents, while a public in-place paragraph mutation saves only the owner-free `ordinary` document and fails the three documents whose unrelated controls after the target table retain `sdt` namespace owners. The bridge therefore qualifies direct publication with the existing cached `plain_local_edit_blocked` fact. When that fact is false, the part has no retained nested owner and no shadowed serializer prefix, so `replay_nested_namespace_declarations_with_spans` returns the serialized bytes unchanged at `crates/rdocx/src/document.rs:4125-4127` and the model-only edit flushes like the existing direct body paragraph path. When it is true, the candidate is published through the checked fallback, which rewrites the source part and keeps the save successful. The fact is cached per source and is not a per-setter body rescan. Documents with compatible unrelated owners keep their existing checked success and are not refused.

`PyRun::bind_current` changes from `paragraph.native(&document.inner)` at `crates/rdocx-py/src/run.rs:72` to `document.paragraph_route(&paragraph, None)`. `paragraph_route(None)` uses `indexed_paragraph_location` (`crates/rdocx-py/src/document.rs:10209-10223`), which uses `self.indexes.cell_paragraphs` for a cell location (`crates/rdocx-py/src/document.rs:10174-10203`). `from_document` builds those indexes from `WordIndexProjections::of(&inner)` when the inventory does not supply projections (`crates/rdocx-py/src/document.rs:11488-11517`). `WordIndexProjections::of` calls `document.cell_paragraph_story_locations()` (`crates/rdocx-py/src/document.rs:5187-5198`). For an ordinary open, the projection is complete. If it is missing or empty, `paragraph_route` falls back to `location.native(document)`. The design preserves that fallback.

`PyParagraph::bind_current` already uses `paragraph_route` at `crates/rdocx-py/src/paragraph.rs:422`. No change there.

`paragraph_route` under `debug_assertions` still calls `location.native` at `crates/rdocx-py/src/document.rs:10217-10218`. That assert reaches `cell_paragraph_story_location`, which clones at `crates/rdocx/src/document.rs:35479`. The issue lambdas evaluate `paragraphs[0]` inside `ms()`. Release Python 3.12 does not run the assert. Keep the assert. A debug counter around the whole Python call may observe that native call. ### Direct cell gate proof

`CT_Tc::paragraphs` returns `collect_paragraphs` (`crates/rdocx-oxml/src/table.rs:2267-2282`). `collect_paragraphs` pushes every `CellContent::Paragraph` and recurses into `CellContent::ContentControl` via `sdt.collect_paragraphs(SdtOwner::Cell, ...)` (`crates/rdocx-oxml/src/table.rs:2484-2494`). `CT_Sdt::collect_paragraphs` for `SdtOwner::Cell` includes `SdtContent::Paragraph` and `SdtContent::Table`, because `owns_content` allows both for `Cell` (`crates/rdocx-oxml/src/content_control.rs:1155-1171` and `crates/rdocx-oxml/src/content_control.rs:2567-2593`). `CT_Tc::paragraphs_mut` filters only `CellContent::Paragraph` and excludes `CellContent::Table` and `CellContent::ContentControl` (`crates/rdocx-oxml/src/table.rs:2274-2282`). Direct `CellContent::Table` is excluded from both.

Therefore, if the two counts are equal, no content control contributes a paragraph. A control with zero paragraphs contributes nothing to either sequence. A control with any paragraph, including a paragraph inside a control-owned nested table, would increase the reader count and fail the gate. A direct nested table is excluded from both. When the counts are equal, the reader sequence is exactly the direct sequence in source order, so the direct ordinal `paragraph` selects the same physical `CT_P` in both accessors. This is the proof required by the design contract-closure pass. It is not the donor's last-paragraph heuristic.

The gate also rejects `paragraph >= direct_count` and zero direct paragraphs. The gate is checked on an immutable borrow before any mutation or live invalidation. The reader count uses `CT_Tc::paragraphs()` and the direct count counts `CellContent::Paragraph`, so the two sequences compared here are the same ones the mutable publish reacquires at `crates/rdocx/src/table.rs:2291`.

### Python table collection

`CT_Body::tables` stays as it is. It still builds a `Vec` at `crates/rdocx-oxml/src/document.rs:4541-4550`, and native `Document::table` still calls `.nth` at `crates/rdocx/src/document.rs:34736-34758`. The issue scripts never call that native lookup. Changing it would be extra scope, so this story drops the lazy iterator and drops any test whose only job is that iterator.

`Document.tables` returns a `PyTableCollection` (`crates/rdocx-py/src/document.rs:16334`). `PyTableCollection.__len__` uses `cached_body_table_count` (`crates/rdocx-py/src/document.rs:10429-10431`), which reads `indexes.body_tables.len()`. `PyTableCollection.__getitem__` calls `PyTable::bind_current` (`crates/rdocx-py/src/table.rs:363-413` and `crates/rdocx-py/src/table.rs:482-510`), which uses `indexed_table_location` first (`crates/rdocx-py/src/document.rs:10225-10245`) and falls back to `TableLocation::new(...).native(...)`. Therefore `doc.tables[0]` does not walk the body. The case-3 fix is the direct cell route.

### Validation and failure atomicity

The fast path changes only where the edit is applied. It does not skip scope validation, style graph validation, paragraph validation or run validation. A cell with any content-control paragraph keeps the checked route. Candidate serialization, section ownership, strict lexical qualification, relationship admission, comment removal reconciliation and the retained-owner qualification remain. Strict validation is a sufficient direct-path qualification, not a refusal gate. A candidate that cannot be qualified locally, including a strict-unqualified retained fragment or a document with retained nested owners, is published through the existing checked route with the same edited fragment. A newly introduced U+0000 is refused by that checked route through the existing OPC character policy. A failed closure or admission leaves the original document, package, layout Arc and style unchanged. A preflight refusal invokes the closure zero times.

The styles skip applies only to an unchanged part with a successful open-time proof. A changed model is compared by value, serialized, checked for root attributes, and then written. `Arc::make_mut` gives copy-on-write custody, so a staged clone cannot mutate the original model. A malformed styles replacement returns before `set_part`. A failed cell closure leaves the live paragraph unchanged. A failed cell closure or candidate admission also leaves the layout caches and the checked-body refusal memo unchanged, because the bridge performs no mutable document access before admission. A successful direct edit assigns the candidate first and calls `invalidate_layout` after the assignment.

## Rejected alternatives

- Donor last-paragraph content-control check. It can pass for a mixed cell and then edit the wrong physical paragraph. The count comparison plus the control-owned nested table case is required.
- Warm the cell-place case. It weakens the reported first-operation cost contract. The cold `n=3` check including the first stays.
- Replace the timing ratio with counters. Counters complement the ratio and cannot replace it.
- Keep unconditional `to_xml` on every flush. It is the measured A1 defect.
- First-flush serialization witness as the default. It puts one O(styles) serialization inside the first timed edit and can fail A1 for `try_replace_text`. The proof runs at open.
- Equal-model skip without an open-time proof. The unreachable-failure claim is withdrawn. The skip is conditional on the proof.
- Fail open on a parseable but unserializable styles part. It would change the current open and save contract without an acceptance requirement. The design records the proof failure and refuses the skip at flush, preserving the existing failure point.
- Treat `from_xml` `Err` as changed and rewrite the part. It can silently replace malformed bytes. Parse failure returns before `set_part`.
- Edit the live cell paragraph in place without a clone. A closure that mutates then returns `Err` would leave partial mutation. The clone and publish barrier is required.
- Resolve the table with `table_mut` before the closure. That lookup clears the layout caches and the checked-body refusal memo before a fallible edit, so a failed closure would change live derived state. The immutable eligibility order is required.
- Assign the candidate immediately after closure `Ok`. It skips `ContentFragment::paragraph`, section ownership, strict lexical qualification, relationship and comment checks, retained-owner qualification and checked publication. A U+0000 candidate would be installed and fail only at a later save. Candidate qualification is required.
- Rerun the closure in a checked fallback. `FnOnce` is invoked at most once overall. The fallback consumes the already-built candidate fragment or the original closure on the source route, never both. A preflight refusal invokes neither and changes nothing.
- Clone the whole document to hide the early invalidation. The direct path avoids mutable access before admission and does not use a whole-document clone as a workaround. The checked fallback uses the existing publication only when the candidate needs it. It is also not used to qualify retained-owner replay, because the existing cached `plain_local_edit_blocked` fact already answers that without a per-setter clone or body scan.
- Add a new public refusal for an unqualified candidate. The candidate is admitted through existing checks and published through the existing checked route. No narrower closure API or new refusal policy is introduced. A strict lexical error is not a refusal. It selects the checked fallback, which decides actual legacy acceptance.
- Treat `validate_strict_xml_1_0` as a blanket refusal gate. It checks UTF-8, XML 1.0 characters, qualified names, namespace binding, attribute value syntax and expanded-attribute uniqueness, which is broader than the character-only OPC writer. A blanket gate would newly refuse retained fragments the existing checked publisher accepts. It is used only as a sufficient direct-path qualification.
- Rescan the whole body on each setter to decide replay. The existing `plain_local_edit_blocked` fact is cached per source. A per-setter scan or clone would break the bounded edit contract.
- Use the direct model-only path on a document with retained nested namespace owners. Root's counterfactual shows the later save can fail to identify the retained owner. The checked fallback keeps the existing save success without refusing the document.
- A new general `Cell` API. The existing `paragraph_count` and `paragraph_mut` are enough for the gate. The hidden `Document::edit_cell_paragraph` bridge is not a general `Cell` API.
- A new trait, crate, module, file, test binary or feature flag. No second implementer or named flag consumer exists today. The one generic on `edit_cell_paragraph<T>` is not in this rejection. Its two current return types are named above.
- Skip style graph or paragraph validation for speed. The fast path changes only the edit location.
- Change the A282 thresholds or the issue scripts. The user thresholds stay 3.0, 3.0 and 2.0.
- Adopt the donor README, crate README and `scripts/readme_doctests.py` hunks. F-X275 and the integrator own the final union measurement rows. F-X282 does not change README or archive baselines.
- A lazy `CT_Body::tables` rewrite. The timed Python path does not call it. Leaving the current `Vec` iterator is the smaller diff.
- Treat the F-X272 provider contract as a dependency. There is no product provider edge.
- Treat `doc(hidden)` as if it removed the public surface. `get_part_shared` is additive public surface and enters the SemVer baseline.
- Adopt a donor timing or donor CI as a pass. Donor measurements are historical observations, not passes.
- Treat Root's counterfactual probes as this author's independent discovery or as a current-source performance qualification. They are Root-authored evidence about the existing APIs, the acquisition side effect, the strict-validator breadth and the owner-replay failure class. All timings remain unexecuted.
