## Approach

Implement private stored_package_issues/stored_xml_fault and the small namespace-aware presentation/shape/table scans in existing rpptx/src/lib.rs. Reuse current OPC parts/content_types/relationships APIs, existing issue types/Display, existing private Presentation::from_read_package and same-file PptXmlScope/PptXmlNames namespace/name/path primitives. Use the existing lexical helper for its proved frontier. Do not create another namespace framework. rpptx already has a production zip dependency. Do not import the crate-private rpptx-oxml NamespaceBindings or root_schema_boundary as if callable from this crate. No public visibility expansion, new module/file/crate/trait or general XML framework.

1. std::fs::read maps through existing OpcError::Io into rpptx::Error::Package. OpcPackage::from_reader(Cursor::new(bytes)) uses its current PackageReadLimits::UNBOUNDED path. Preserve that exact entry point. This API has no new limits parameter or quota. Do not alter bounded/unbounded open behavior or inspect/save the package with new mutations.
2. If OPC loading returns the existing InvalidXmlCharacter, return the originally specified single InvalidXmlChild issue with the actual part, root path and code point. Every other OPC error propagates unchanged before stored scanning. Current source produces this variant for writes, while future B may produce it on open. Handling the already-existing variant is not a dependency on B or evidence that B's open refusal exists. Metadata parse/ZIP failure can terminate validation before per-part scanning. Do not label that failure as completed validation of all parts or reword it into a successful Vec result.
3. On successful OPC loading, check original XML for every indexed unique OPC identity. package.parts contains unmodified ordinary source bytes but excludes content types and all .rels. zip_entries serializes metadata and is unsuitable as the original-source validator. Borrow ordinary XML bytes from package.parts. Use a read-only ZipArchive over the retained original file bytes to recover original [Content_Types].xml and .rels bytes only. XML classification follows the existing content-type lowercase-ends-xml rule plus OPC metadata entries, without making extension-only binary parts XML. Sort actual part names for deterministic scan order. Do not serialize, sanitize, repair or save to obtain validator input. Do not introduce a second duplicate-name policy or a central-directory scanner. The existing ZipArchive index can collapse physically repeated exact ZIP names. This scan therefore covers the indexed unique OPC identities admitted by the current loader, not every physical duplicate entry. B remains the sole owner of exact duplicate/open-forbidden behavior. Existing OPC loading decides those errors first. Final parent composition must verify B duplicate refusal reaches this file API/CLI before a hidden duplicate can be treated as a clean stored part.
4. stored_xml_fault checks XML1.0 characters, lexical/tokenizer errors, exactly one document root, balanced completion and non-whitespace text outside the root. The existing oxml_core::xml::validate_strict_xml_1_0 supplies lexical name/attribute/reference/namespace checks, but is UTF8-only and does not prove root count. Preserve the existing opaque XML support shown by the OPC UTF8/BOM and UTF16 LE/BE fixtures via a private lossless decoding step matching the existing OPC BOM/signature recognition. This does not add typed PresentationML UTF16 support or claim universal encoding support. Reject malformed encodings without replacement characters. Validate decoded input and separately count roots/depth with the actual reader. Do not reject valid UTF16 opaque XML just because the shared helper accepts UTF8. No package source bytes are changed. This is a source-frontier closure detail for Root audit, not a new encoding framework or public API.
5. Inspect only qualified direct presentation-root child order/membership, including the original notesMasterIdLst-after-sldIdLst and sldSz-before-sldIdLst faults, using the pinned SDK3.0.1 sequence below. In particular accept p:kinsoku in its proper slot. Do not copy the typed root_schema_boundary typo kiosk, admit smartTags as a standard root child, or fix that typed writer in this story. Respect URI-based aliases/default namespace and local rebinding. Preserve original source with no write. Compatibility/extension treatment is specified below, no full-schema claim.
6. For slide/layout/master/notes/handout XML roles, check the exact direct tree, nonvisual-owner and table paths below. spTree/grpSp shape members form a mixed repeating choice, not the rank order assigned by the old helper array. Required cNvPr id/name are unqualified attributes on the correct physical owner only. Count each table independently and only direct qualified cells/grid columns, excluding extension and unsupported foreign Choice payload. Qualified immediate PresentationML members of both Choice and Fallback use the same finite subset. Preserve the specified compatibility wrappers and ignorable/extension islands. No table geometry/merge repair, general required-child validator or MCE engine is added.
7. For each internal relationship of type slide/layout/master/notesSlide/notesMaster/handoutMaster, resolve its target through existing OpcPackage::resolve_rel_target from its actual owning part. Require the matching existing content-type constant. Missing/fallback application/xml is MissingContentTypeOverride. Preserve normal external-target policy and do not confuse relationship owners or add a new dangling-reference scheme beyond existing parsed validation.
8. After stored checks, call existing Presentation::from_read_package(package). If it opens, append existing live validate issues, deduplicated without changing stored-first/native-order semantics. ValidationIssue already derives Eq/PartialEq at lib.rs:1047, so use that existing equality for deduplication. Do not add Debug-based formatting policy. If model opening fails and stored issues exist, return those issues. If no stored issue exists, propagate the actual model error. Preserve input file bytes in every outcome.
9. Route CLI to the public file function. Retain existing Display, success/failure reporting and BrokenPipe behavior. Preserve Python parsed-model implementation and current issue conversion. Add executable agreement controls rather than merely checking a source formatting string.

The original metadata parser failure ordering is retained. This child does not promise recovery of a part inventory from an OPC parse failure.
